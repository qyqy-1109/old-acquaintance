## 一、项目目标与背景

### 目标（从代码结构反推得出的实际目标）

一个**本地单人使用的陪伴型对话助手**，代号「旧识」（她叫沈知夏）。它的重点不在聊天本身，而在**记忆系统**：

- 让她记得住：跨会话记住用户说过的**事实**，而不是靠一次对话的上下文窗口。
- 让她记得准：事实以「提炼后的短句」入库，按语义召回，不带一堆寒暄。
- 让她该忘的忘、该改的改：有遗忘与淘汰，也有「旧记录被推翻」的更新通道。
- 让她分得清「我是谁 / 你是谁 / 我们共同的背景 / 我们聊过什么」——这四件事分别落在四层，不允许串层。
- 全过程**可观测**：网页右侧有状态栏（人设、画像、世界书、记忆统计、跨层矛盾提示），加上「她说错了」一键留证与一套可复现的评测集。

### 背景

- 来自一次「四层记忆架构」的架构练手。【依据 `~/.workbuddy/USER.md`】
- 同一系列的设计文档在另一个工作区：`C:\Users\Windows\Desktop\世界书练手\四层记忆架构-架构基线.md`（载体写的是「方向 B：记忆驱动的文字冒险 + 调试面板」）。
- ⚠️【不确定】当前工作区（`C:\Users\Windows\Desktop\test`）与那份基线的关系没有代码层面的声明。可以确认的差异有两点：①当前实现是**对话助手**形态，没有文字冒险玩法；②那份基线把「第一版不引入向量库、不引入嵌入模型」列为红线，而当前实现**已经在用 embedding 做语义召回**（`qwen3.7-text-embedding`，2048 维）。所以当前实现相对那份基线是**演进/越界**的状态。

## 三、整体技术架构与目录结构

### 架构：MVC + Service（"MVC+S"）

```
View  ──  app/views/index.html（网页） ／ openai_hello.py（CLI）
              │ HTTP(fetch + SSE + Bearer/X-User-Id)   │ 函数调用
```

## 四、核心业务流程

### 1. 一轮流式对话（`POST /api/chat/stream`）

```
用户发消息
 → prepare()  → store.build_messages(system_prompt, question)
      system 段（system_prompt() 内按序组装）：
        ① 当前时间（每轮重新取，带星期；含「摘要里的时刻是当时的记录」免疫句）
        ② 【天气】（高德缓存行，未配密钥则无此块）
        ③ 【用户最近的情绪】（emotion.summary()，没有值得说的就没有此块）
        ④ 【当前状态】（slots 槽位全量，覆盖式更新，上限 12 条）
        ⑤ 性格模板（含自我底座与三级态度预案） + 用户画像
      build_messages 追加：
        ⑥ 【必须遵守的约束】kind=constraint 且仍生效，每轮无条件注入，不走召回
        ⑦ 【已经解除的旧禁忌】relaxed_at 非空的约束——不再当禁令，但保留"有过这回事"
        ⑧ 【此刻的分寸】状态槽位派生（命中消失类状态 → 「默认假设已不成立」）
        ⑨ 【今天说好的事】upcoming(only_today) 的结果，上限 3 条，带时刻级状态标签
        ⑩ 【你和用户共同生活的世界】world 类向量召回 top 3
        ⑪ 【想起来的事】fact/turn 类向量召回 top 3，带时距/过期标注
        ⑫ 【更早之前】滚动摘要（若有）
        ⑬ 最近 10 轮原文（滑动窗口，跳过空回答）
        ⑭ 本轮用户消息
 → SSE meta 事件（召回明细 + prepare_ms；流式对话全程分段计时）
 → stream()：chat_client 流式生成 → delta 事件逐字推送
 → **写记忆已异步**（#068）：正文流完即结束请求，`finish_turn` 被投进
      按 `crc32(uid) % WB_WORKERS` 分片的**每用户串行队列**（同用户按序、跨用户并行、
      退出 `flush(60s)` 不丢轮次、单任务失败不连坐；`WB_WORKERS=0` 退化为同步）
 → SSE done 事件（记忆备注 + 画像备注 + `memory_async: true` + `timing` 分段耗时）
 → 感知与画像/演化也在后台：weather.refresh() / emotion.record()（按 EMOTION_EVERY）/
      每 EVOLVE_EVERY(20) 轮演化 / 每 PROFILE_EVERY(5) 轮画像
```

已知取舍：**前端中途断开时这一轮不会写进记忆**（生成器被关闭，投递不发生）。

### 2. 记忆写入管线（`MemoryStore.add_turn`）

```
1) 追加会话历史（内存 + 待落盘）
2) 滚动摘要：窗口外攒够 summarize_every(6) 轮 → _maybe_summarize()
     摘要提示词硬规则：不把「当时几点」写进摘要（长生命周期存储里的时刻必然过期——
     实际咬过人：摘要里冻着「晚8点31分」，下午三点她说「晚安」）
3) 显式通道：用户说了「记住 xxx」→ 原话直接入库（explicit=True，不参与淘汰）
4) _extract()：一次提炼调用，输出六类
     facts / world（只收长期成立的，一次性事件走 facts）/ constraints / drop /
     selfs（她的经历，第一人称「我…」，只认「我」开头防串层，不许脑补）/
     slots（entity/attr/value 三键齐全才收，覆盖式写入 slots 表）
     提示词里喂：已有世界书+约束（防重复）、最相关的 5 条旧记忆（发现推翻）、
                 最近作废清单（防复活）、当前时间（相对时间→绝对日期）
     提炼失败返回 None：**失败分支必须补齐 6 个位置**——踩过，失败分支少写两个位置，
     于是"提炼失败"这条本该被容忍的路径变成整轮 ValueError、SSE 收尾跟着断
5) drop_memories()：**按 kind 分流**——约束走「解除」（标 relaxed_at，不删不归档，
     因为它没有被推翻、只是不再生效），其余走作废归档（默认软删）
6) _add_memories()：新条目入库前查重（普通 dedup_sim=0.92）；被 world/constraint
     覆盖的普通记忆「就地转正」改 kind，并同步改文本与向量
     写入哨兵：clock.fix_impossible_time()——完成时句式 + 今天的未来时刻
     = 日期锚不可能，回拨到昨天
     入库时解析 event_date（解析不出为 NULL，不硬造）；selfs 走 actor="assistant"
     world 类另走 _world_check() 三态判定：
       duplicate   相似度 ≥0.86 直接判重；否则交给模型判（判不了按新增放行）
       contradict  写新条目 + 作废被推翻的旧条目
       new         直接入库
     判定顺序很关键：**等新条目落库之后才作废旧条目**，顺序反了会出现
     「旧条目没了、新条目也没写进去」的空窗。作废时会打印一行提示
     （世界书是可手工编辑的唯一真相，自动改必须让人知道）
7) _compensate()：作废后问一次「旧条目里还有哪些仍成立」，捡回被连坐的信息
8) 第二道兜底：新内容（含用户原话）出现状态变化词（搬到/不在了/不用忌了…）
     → _find_superseded() 主动追问「哪些旧记忆被取代了」
9) on_world 回调 → 新 world 条目写回 world.json
```

### 3. 召回与遗忘

- 召回：查询文本 → embedding → 与内存中的 numpy 矩阵做余弦相似度 → 按 kind 过滤 → top_k + 阈值 0.45 → 命中计数 +1（攒到 `save()` 批量落盘）。
- 遗忘：权重 = (1 + 命中加成，封顶 3.0) × 时间衰减（半衰期 30 天）；超过 2000 条时淘汰权重最低的，**world / constraint / explicit 不参与**。
- 作废：默认软删（`archived_at`，归档上限 500 条）；`/mem del`、`/forget` 是物理删（用户明确意图）。

### 4. 世界书双向同步

`world.json`（可手写）→ 启动 `sync()` 灌进向量库；提炼出的新条目 → `on_world` 回调写回 json；对话判定作废且命中 world 条目 → `on_drop` 回调从 json 删除。构造时先 `_absorb_store()` 回收向量库里有、json 里没有的条目，避免 sync 误删。

入库时的同主题互斥：**不能靠相似度筛候选来查矛盾**——实测「养了只叫年糕的橘猫」和「家里没有养任何宠物」相似度只有 0.50，语义互斥的两句字面几乎不重叠，任何阈值都拦不住。所以条目数 ≤ `WORLD_FULL_REVIEW`（30）时直接**全量复核**一次，一次调用换「不可能有矛盾并存」；条目多到不适合全量时才退回相似度近邻。模型说「矛盾」但没给出具体是哪条原文时，退化成「新增」——不敢凭一句结论就删旧条目。

### 5. 开场白 / 画像 / 感知 / 留证

- 开场白：页面打开或刷新 → `GET /api/greeting` 每次重新生成（先清掉上一条，避免堆满窗口）；提示词里把「今天及未来 7 天的约定」放最前，**约定先判状态**——已过或已有结果的绝不邀约（最多轻轻回顾），确实没发生才催促，拿准不准就不提；问候必须符合当前时段（修过「晚上八点催早上十点的约」的实际事故）。记忆全空时回退 `personality.json` 里的固定开场白。`/api/state` 只回缓存值，避免每轮重复付费。
- 画像：每 5 轮用最近 10 条消息跑一次 `analyze()`，输出「更新后的完整画像」，只增不删、以对话为准。
- 感知：`finish_turn()` 里天气缓存过期就刷新（失败静默）、按 `EMOTION_EVERY` 周期判一次情绪（jev，conf<0.6 不记录，轨迹留 14 天）；下一轮注入【天气】【用户最近的情绪】各一行。
- 性格演化：每 `EVOLVE_EVERY`(20) 轮用游标只复盘**新增**对话（小步、可归因、可回滚）；退出钩子兜底，没有新对话不空跑模型。
- 留证：「她说错了」→ `mark_wrong()` 把上一轮的完整现场（问题、回答、召回明细、注入的每个 system 块、模型名）追加到 `feedback.jsonl`；`_recorded_ts` 防止连点重复记。**这套留证已经实际立功 4 次**（摘要时刻污染、天气预报只到今天、按钮卡死连带诊断失效、未来时间戳记忆）。

## 五、关键数据与接口设计

### 1. 数据模型：四层 + 记忆内部分四类

| 层 | 文件 | 内容 | 关键约束 |
|---|---|---|---|
| 性格 | `personality.json` | current + history（最多 20 版） | `evolve()` 白名单 `EVOLVABLE`；`name`/`scope`/**自我底座**不可被对话改；数组条目必须含中文 |
| 世界书 | `world.json` | entries[{text, source, ts}] | 唯一真相、可手写、不参与遗忘 |
| 画像 | `user_profile.json` | summary/facts/preferences/expertise/communication/topics/version | 独立模型提炼，只增不删 |
| 记忆 | `memory.db` | memories / messages / summaries / pending / **slots** / **events** / meta（多张表） | 存**提炼后的事实短句**，不存原文；slots 是覆盖式状态（实体·属性·值），events 是只增的机制埋点 |
| 情绪轨迹 | `emotion.json` | [{ts, mood, confidence, intensity, quote}]，只留 14 天 | jev 判定，conf<0.6 不记录；沉默优于噪音 |

记忆的四类（`kind`）与各自命运：

| kind | 内容 | 召回 | 遗忘/淘汰 |
|---|---|---|---|
| `fact` | 提炼出的事实短句（用户侧 + **她的经历** `actor=assistant`） | 按相似度 | 参与 |
| `turn` | 旧格式迁移上来的整轮原文 | 按相似度 | 参与 |
| `world` | 世界书条目（只收长期成立的设定） | 按相似度 | 不参与 |
| `constraint` | 硬性要求/禁忌 | **不召回，每轮无条件注入** | 不参与（`relaxed_at` 非空 = 已解除，改成注入「已解除」，不再是禁令） |

两条**不在 kind 表里**的机制（它们是"状态"，不是"叙事"）：

- **`slots` 状态槽位**：`(entity, attr)` 主键的覆盖式更新，「现在是什么样」的一等公民——年糕在哪不该靠相似度碰运气。注入时全量（上限 12）；其中出现消失类状态时派生出【此刻的分寸】，状态恢复后那条分寸**自动消失**。
- **`events` 机制埋点**：只增的事件流水，不参与召回也不参与注入，只服务于「机制到底在不在跑、成功率多少」。

每条 `fact` 还带 `event_date`（入库时解析的事件日期，NULL=无日期；时间轴 = `event_date` 非空条目按日期倒序的视图）。约束单独一类是必须的：「给我推荐点零食吧」和「我对花生过敏」没有字面重叠，纯向量召不回来，而约束本就该永远在场。

### 2. HTTP 接口

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/state` | GET | 状态栏数据（模型、人设、画像、记忆统计、世界书、启动时对账结果） |
| `/api/greeting` | GET | 按此刻最新记忆重新生成开场白 |
| `/api/chat` | POST | 非流式一轮 |
| `/api/chat/stream` | POST | 流式一轮，SSE **五种事件**：`meta`（召回明细）→ `delta`（正文）→ `done`（记忆/画像备注）→ `audio`（音频分片，base64）→ `audio_end`（音频收尾） |
| `/api/feedback` | POST | 留证上一轮现场到 `feedback.jsonl` |
| `/api/command` | POST | 执行 `/mem` `/world` `/clear` 等斜杠命令 |
| `/api/world` | GET/POST | 世界书列表 / 手写一条 |
| `/api/world/{index}` | DELETE | 删除某条 |
| `/api/clear`、`/api/forget` | POST | 清会话 / 遗忘长期记忆 |
| `/`、`/favicon.ico`、`/api/health` | GET | 页面（禁缓存）、内联 SVG 图标、健康检查 |

请求体由 `app/controllers/schema.py` 的 Pydantic 模型校验（`ChatIn` / `CommandIn` / `WorldIn`）。

### 3. 斜杠命令

`/mem`（统计，已区分"现役约束 / 已解除"）、`/mem check`（跨层对账，只报告不改数据，启动时自动跑一次）、`/mem dead` + `/mem del <序号>`（唯一「按数据删」入口）、**`/mem events`**（机制事件聚合 + 最近明细，别名 `/mem 事件`）、`/world [描述|del N|tidy|reload]`、`/timeline`（事件时间轴，别名 `/时间轴`）、**`/slots`**（状态槽位，别名 `/状态`）、`/user`、`/profile`、`/personality [描述|evolve|reset]`、`/clear`、`/forget`。

（`/timeline` 与 `/slots` 都已在 `COMMANDS` 白名单里，命令行版同样可用。）

### 4. SQLite 表

- `memories`：一条记忆一行；`vec` 是 BLOB，与元数据同排一行（没有平行数组，消灭了下标错位）；`archived_at`/`archived_reason` 实现软删归档；`event_date TEXT`（事件日期，入库时解析，NULL=无日期）、`actor`（user/assistant）、`relaxed_at REAL`（约束失效时刻，NULL=仍生效）三列由 `connect()` 里的 PRAGMA 检查 + `ALTER TABLE` 自动补上（`CREATE TABLE IF NOT EXISTS` 不会给旧表加列）；索引 `idx_active`、`idx_kind`。
- `messages`：(session, seq) 主键；`greeting` 标记开场白消息。
- `summaries`：每 session 的摘要 + 已摘要游标。
- `pending`：暂时没有向量的记忆，下次启动补算。
- `slots`：(entity, attr) 主键的覆盖式状态槽位。
- `events`：机制埋点流水（append-only，`ts/kind/session/payload`），超 `events_keep` 在 `save()` 里修剪最老的。
- `meta`：键值（迁移来源标记）。

并发：`check_same_thread=False`（FastAPI 同步接口跑线程池）+ `threading.RLock` 守多语句事务 + WAL 日志。
