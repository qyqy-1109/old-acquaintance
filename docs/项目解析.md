## 0. 一句话与十个要点

**一句话**：它不是聊天界面，是一个**有记忆、会成长**的陪伴者——难点不在对话，而在"**记得住、记得对、知道什么时候该忘**"。

| # | 要点 | 一句话 |
|---|---|---|
| 1 | 长期记忆存**提炼后的事实短句**，不存对话原文 | 存原文召回又贵又稀；短句一条一句、召得准、注入便宜 |
| 2 | **字面零重叠但必须记得的东西不走召回** | 约束、已解除的旧禁忌、"此刻的分寸"、今天说好的事、说话偏好——无条件在场 |
| 3 | 作废是**软删归档 + 补偿捡回** | 物理删会连坐：实测 5 个场景 2 次把捆在一起的信息一起抹掉 |
| 4 | 世界书**三态判定**（重复/矛盾/新增）+ `world.json` 唯一真相 | 矛盾不能靠相似度：语义互斥的两句相似度可能只有 0.50 |
| 5 | 遗忘是**加权衰减**，不是先进先出 | `(1+min(0.2×命中,3)) × 0.5^(天数/30)`；世界书/约束/明说记住的不参与淘汰 |
| 6 | 人格演化**有护栏 + 有人拍板** | 底座与名字不可改；冲突条目进"待确认"由人裁定，采纳时绕过检查 |
| 7 | 每次"她说错了"都会**变成一条可执行的话** | 提炼 → 去重 → 攒独立命中 → 够强才进"待确认"；不够强只注入 |
| 8 | 机制**必须可观测**：埋点表 + 留证文件 | "某机制到底跑没跑"是查表，不是靠回忆 |
| 9 | **失败要可见**（本仓库最硬的一条） | 提炼/向量化/摘要/淘汰达不成——都要留事件 + 日志 + 给用户的话术 |
| 10 | 评测**不打分**，做四件套 + 基准指标 | 人格的本质是关系与一致性，不是刻度 |

## 1. 产品定位与不变式

**定位**：一个本地运行、单人自用起步的陪伴型对话系统；形态是"**每人一个她**"（每用户一套数据 + 一个实例）。

**十二条不变式**（写进代码注释的"设计纪律"；出处见第 17 节）：
1. 长期记忆存**提炼短句**，不存原文。
2. **写是增量的**：新增 INSERT、作废 UPDATE，不做"改一处全量重写"。
3. 作废＝**软删**（`archived_at`），物理删会连坐。
4. **向量与元数据成对写入**；锁**不跨模型调用**（跨网络持锁会拖死服务）。
5. 一次计算里**绝不重复读共享引用**（否则向量形状不一致 → 召回直接 500）。
6. **失败要可见**：批量向量化失败 → 整轮不写 + ERROR + 事件；上限达不成 → 报警；人格检查器故障 → 放行但留痕。
7. **留档必须有出口**：归档 500 条、事件 5000 条，超了删最老。
8. **宁可漏也别误**：判不清"不同侧面 vs 矛盾"时选"新增"；拿不准哪天就不写日期。
9. **工具给事实，人格给话术**：感知层只提供"现在几点/天气/情绪"，不说该怎么安慰。
10. **拦下 ≠ 丢弃**：被护栏拦下的人格改动要留档等人拍板。
11. **无效令牌一律 `None`**，绝不"解析不出来就退回默认用户"。
12. **误判放大比沉默更伤**：情绪低置信度不记录、没有值得说的就不注入。

```

├── accounts.db                 # 账号库（全局）
```

## 3. 记忆层：四层 + 三类"状态"

### 3.1 会话原文（`messages`）

全量存、一条不丢；只有最近 `window=10` 轮（20 条消息）进模型。开场白标记 `greeting=1`（用于区分"自动问候"与真实对话）。

### 3.2 滚动摘要（`summaries` + 游标）

- 触发：窗口外的部分攒够 `summarize_every(6) × 2` 条才做一次；`pending_end = len(history) - window*2`。
- **成败用 `is not None` 判定**：失败返回 `None`、窗口外无内容返回 `""`；两者混起来会让游标照推 → 那批对话**永远不会再被摘要**（踩过）。
- 失败：**不推进游标** + 退避 `summarize_retry_delay(60s)`（模型长期不可用时不至于每轮白烧一次调用）。
- 摘要与游标**同一把锁里一起写**（否则并发下留下"摘要换了、游标旧了"的半截状态）。

### 3.3 长期记忆：**存短句不存原文**

- **取舍**：存原文召回回来一大坨、token 贵、有用信息被寒暄稀释；存短句一条一句、召得准、注入便宜。代价是每轮多一次提炼调用（`extract_every` 节流；`auto_extract=False` 可退回旧行为）。
- **召回线 0.45**：46 条真实用例实测出来的（存原文时 0.30 都嫌松，存短句后必须收紧）。
- **去重线 0.92**：高于它视为重复，不写第二条。
- `top_k=3`（事实）、`top_k_world=3`（世界书）。
- **弱相似标注**：入选且 `sim < 0.50` 的条目标 `weak`，注入时提示"弱相关"——**交给模型自己判断，不硬过滤**（0.45 是实测线，拍脑袋收紧会伤别的召回）。

### 3.4 遗忘与生命周期

| 机制 | 口径 |
|---|---|
| 权重 | `weight = (1 + min(hit_bonus(0.2) × hits, hit_cap(3.0))) × 0.5^(age_days / half_life_days(30))`，`age` 从**最后一次命中**算起 |
| 淘汰 | 仅当条数 > `max_memories(2000)`；候选＝权重升序中排除 `world`/`constraint`/`explicit`；**候选不够时报警**（否则上限静默失效） |
| 软删（归档） | 被推翻/与世界书矛盾的条目 → `archived_at` + `archived_reason`；归档保留 `archive_keep(500)` 条，超了删最老 |
| 物理删 | 只用于两类：**容量淘汰**、**用户明确要求删除**（`/mem del`、`/forget`） |
| 作废 + 补偿 | 作废后必问一次"旧条目里还有哪些仍成立"，最多捡回 3 条重新入库（模型 40% 情况会整条作废，这一步是那道指令的兜底） |
| 第二道兜底 | 新内容或**用户原话**里出现状态变化词 → 主动追问"哪些旧记忆过期了"（实测："公司搬到滨江"4 次里 0 次自动作废旧条目） |
| 约束"解除" | 不是删除，而是标 `relaxed_at`；注入时改说"已解除、别再当禁令，但你要记得有过这回事" |

### 3.5 状态槽位（`slots`）

"现在是什么样"的一等公民：年糕在哪、你的城市、天气状况。**覆盖式更新**（值没变不写）；数量天然有限（实体×属性），注入时按上限常驻。与叙事记忆的分工：**事件进时间轴、状态进槽位**——"年糕在哪"不该靠相似度碰运气。

### 3.6 时间轴（`event_date`）

- 写入时把"明天早上"换算成**绝对日期**存进 `event_date`（写入时换算、读取时不猜：读取时再解析"下周三"时间一过必然错）。
- **存量重锚**：换算法前的条目按**它自己的 ts** 重写相对词，旧向量作废待补算。
- **时刻哨兵** `fix_impossible_time`：完成时句式 + 今天的未来时刻 = 日期锚不可能 → 回拨到昨天（例：19:50 写入"晚上九点半也没有再疼"）。
- 注入的只有 **`upcoming(only_today=True)` 前 3 条**（"今天说好的事"）；完整时间轴目前**只做可见性**（`/timeline`），要不要注入等真实使用说话。
- 过期约定**不再冒充待办**：`_is_stale_plan` 只判"过期 + 像承诺（`PLAN_COMMIT`，不含中性的"见面/碰头"）+ 未完成"三者都成立才从召回里跳过；**数据仍留在库里**（时间轴、对账照旧看得到）。

### 3.7 世界书（`world.json` + `KIND_WORLD` 条目）

- `world.json` 是**唯一真相**（可手写）；启动 `sync()` 灌进向量库；提炼出的新条目经回调写回文件。
- **三态判定**：相似度 ≥ `world_dedup_sim(0.86)` 直接判重；世界书条数 ≤ 30 时做**全量语义复核**（矛盾不靠相似度筛候选）；超过 30 条才退回相似度近邻 top6 且 ≥ `world_review_sim(0.72)`。
- 判 `contradict` 必须给出**库里真实存在**的 stale 原文，否则退化成 `new`（防模型幻觉造句子）。
- 判定失败一律按 `new` 放行（**宁可漏也别误**）。
- 世界书**不参与遗忘、不参与淘汰**。

### 3.8 约束（`KIND_CONSTRAINT`）

- **不能靠相似度召回**（"给我推荐点零食"和"我对花生过敏"几乎无字面重叠），所以**每轮无条件注入**，上限 `max_constraints(12)`。
- 提示词明说：这些**同时也是"他希望你记得的事"**，相关时要讲出来——只写"不要违反"会被读成"默默照做就够了"（实测漏说 8/8 → 3/8）。
- 不参与遗忘、不参与淘汰；被放宽时走"解除"语义（见 3.4）。

| 18 | 汇总给用户的备忘 + **`turn` 事件**（条目数/作废数/捡回数/重复数/本轮 llm 与 embed 次数/stale 数） | — | `turn` | — |

**"就地转正"**：同一句话从"事实"升级成"约束/世界书"（用户原样再说一遍禁忌），走覆盖而不是新增；此时 **kind/text/ts/向量一起落库**（只改内存会导致重启回退 + `world.json` 与库不一致 → 多出重复条目）。

**请求路径 vs 后台**：整段写入在 `#068` 之后走**后台 worker**（按用户分片，同用户天然串行；`WB_WORKERS=0` 可退化成同步）；流式响应的 `done` 只带 `memory_async` 标记。

## 5. 读取路径（一轮对话看到什么）

`build_messages()` 组装 11 个块，**顺序是刻意的**：

| 序 | 块 | 触发 | 为什么不靠召回 |
|---|---|---|---|
| 1 | system：`【当前时间】`/`【天气】`/`【用户最近的情绪】`/`【当前状态】`（槽位）/人格 render/画像 | 各自开关与内容非空 | 模型不知道"现在"，它说的"今天"就是猜的 |
| 2 | `【必须遵守的约束】` | 有约束 | 与当前问题常零字面重叠 |
| 3 | `【已经解除的旧禁忌】` | 有解除项 | 既撤禁令、又保住"有过这回事" |
| 4 | `【此刻的分寸】` | 由槽位派生的 `behavior_hints()` | "记忆里明明有、行为上照旧"缺的就是这一步 |
| 5 | **【他在意的】**（反馈学来的说话偏好） | `opinions(limit=3)` 非空 | 说话方式层面的偏好，空则**不留空气块** |
| 6 | `【今天说好的事】` | `upcoming(only_today)` 前 3 条 | "早上好"与"9月23日约好溜猫"零重叠 |
| 7 | `【共同的世界】`（召回世界书） | top_k_world | 语义召回 |
| 8 | `【想起来的事】`（召回事实） | top_k，`weak` 的标"弱相关" | 语义召回 |
| 9 | `【更早之前】`（滚动摘要） | 摘要非空 | — |
| 10 | 滑动窗口原文 | 恒有（最近 10 轮） | — |
| 11 | 当前问题 | 恒有 | — |

**召回（`recall`）**：一次 embedding → 全库余弦相似度 → 降序扫到 `< 0.45` 立即 `break` → `kind` 过滤 → 过期约定跳过 → **命中计数 +1**（`hits`/`last_hit`，攒到 `save()` 一次落盘）→ 返回 `{sim,text,kind,weak}`。
**排序只看余弦相似度**：遗忘权重**不参与召回排序**，只参与容量淘汰（这一点最容易误读）。
**向量复用**：一轮里两次召回共用同一个查询向量；**记忆库为空时不调 embedding**。

## 6. 反馈回路：「她说错了」→ 说话倾向

（这条链以前是**只写不读**的死链路：前端有按钮、后端有接口，但没有任何东西消费它。）

```
点「她说错了」+ 备注
   ├─ 写 feedback.jsonl（原始证据，永留；防连点重复记）
   └─ 同步提炼（用户在等结果，所以不丢给 worker）
        ├─ 闸门：is_style_issue=false（她记错了事实）→ 不收，回复里说明分流
        ├─ 闸门：topic/text 为空 → 不收
        ├─ 闸门：模型自报 confidence < 0.6 → 不收（实测它虚高到 0.95，只配当闸门）
        └─ 收下 → upsert opinions（topic 去重）
             独立命中键 = 「会话@日期」（真机上会话恒为 default，只看会话 id 永远到不了 2）
             hits 只在键新增时 +1；notes 数带备注次数
             展示用置信度 = 1 - 0.5^hits（1 次 0.5 / 2 次 0.75 / 3 次 0.875）——**不落库，现算**
   ├─ 每轮注入【他在意的】最多 3 条；≥0.75 说"他不喜欢"，否则"他好像更希望"
   └─ 晋升：hits ≥ 2 且 notes ≥ 1 → 生成 patch 进 /personality pending（**等人拍板，绝不自动生效**）
```

**倾向文本必须"三件套"**（正面做法 + 点名失败动作 + 篇幅约束）——这是三轮 220 次调用测出来的：只说"给出明确态度"时她会在该表态时反问、写长、加铺垫（0/3）；写成"两三句说清你的判断和理由；别反问、别让他先补充背景、别两头都说"才 3/3。
**注入框法不能省**（"不是硬性约束…相关的时候照做…不要点破来源"）：实测去掉它，误用（把无关倾向硬套）从 0 涨到 4~6。
**`patch` 由服务层拼**（原有 `behavior` + 新条目）——`evolve` 对数组是**替换**语义，只发新条目等于删掉人设里别的话。

## 7. 人格层

**字段**：`name` / `identity` / `traits` / `tone` / `values` / `behavior` / `speech_habits` / `greeting` / `scope`（`can`/`cannot`/`boundary`）＋**自我底座** `origin` / `family` / `daily_life` / `cares` / `favorite_places` / `self_attitude`（三级预案：打哈哈 → 半承认 → 兜底承认但立场不变）。

| 类别 | 字段 | 依据 |
|---|---|---|
| **不可被对话改** | 名字、知识边界 `scope`、来历与家庭等固定底座 | "名字是用户定的，身世是**她的过去**——被对话改写就不是过去了" |
| **可演化（白名单）** | `identity`/`tone`/`greeting`/`traits`/`values`/`behavior`/`speech_habits`；`cares`/`favorite_places` 仅追加且经人审 | 偏好可以长大，旧条目不能被演化冲掉 |

**护栏 `_sanitize`**：字段白名单；字符串必须含中文且 ≤120 字；数组单条 ≤60 字、去重、截断 8 条；**空数组不清空**；一次砍掉一半以上直接拒绝。（依据：没有护栏时模型会把"用户是个理性派"写进 behavior，甚至整段换成英文。）

**演化流程**：`evolve(patch)` → 改动前快照入 `history`（留 20 版）→ **应用前跑一致性检查** → 冲突条目**摘出来**（不是整批作废）→ 进"待确认" → 人用 `/personality pending` + `accept/drop N` 拍板（**采纳时绕过一致性检查**——护栏只负责指出冲突，决定权在人）。
**回滚**：`/personality reset` 弹回上一版快照。
**节奏**：每 `EVOLVE_EVERY(20)` 轮复盘一次新增对话；失败时游标不推进（下个检查点重试）；进程退出前兜底跑一次。

**日常选择（T87）**：只有对方明确问她自己想选什么，才把 `favorite_places` 与 `life_events` 中来源为 `model` 的近期选择补进这一轮提示词；最近 12 条里最多取 3 条自主选择。提示要求选择有出处，且不把偏好或流水扩写成未记录的过去细节，但**提示词不构成事实核验**。`finish_turn()` 对这类提问记 `agency_response`，若回答出现「都行 / 随你 / 就当我没说」等让位词则记 `agency_yield_candidate`，两者互斥、可从 `/mem events` 统计。后者只是待复核的字面候选，**不改写原回答**。

## 8. 感知与表达层

### 8.1 时间感知（`utils/clock.py`）

- **路线选择**：**写入时换算、读取时不猜**——读取时再解析"下周三"是哪天，时间一过必然算错。
- **绝对日期只认三种写法**：`YYYY年M月D日/号`、`YYYY-M-D`、`M月D日/号`；认不出就不标（**宁可少标，也不能把无关数字当日期标错**）。
- **相对词兜底表顺序有讲究**：长词在前（"大后天"不能被"后天"先匹配）；`明天/明日 +1`、`今天/今日 0`、`昨天/昨日 -1`、`前天 -2`。
- **时距标注跨度上限 180 天**（超了多半是误识别，不标）。
- **无年份时的判定**：优先当年；若按当年算早于"今天 −180 天"，改判明年。
- **注入格式**：`YYYY年M月D日 周X HH:MM`（带星期是为了让它能推算"下周三"）；注入文本带三条括号纪律——**一律以此为准** / **你就是有表可看，别说看不到表** / **更早摘要里的具体时刻是"当时"，不代表现在**。
- **时刻级解析**（后来升级的）：时段词可选（凌晨/清晨/早上/上午/中午/下午/傍晚/晚上/夜里/半夜…），支持中文数字与"半"；**时段校正**（下午/晚上且 <12 点 → +12；半夜且 ≥6 → 回绕）；**假阳性过滤**（无时段词 + 无分钟 + 非阿拉伯数字 → 不算时刻，"早一点"这种不算）。
- **重锚 `reanchor_relatives`**：按**写入那天**把相对词改写成绝对日期；已有绝对日期的不动、无相对词走快路径。
- **写入哨兵 `fix_impossible_time`**：完成时句式（已经/没有再/不再/好了/结束了/完成了/解决了…）+ 今天的未来时刻 + 文本里有日期词 → **日期回拨到昨天**；四个条件缺一不动（例：19:50 写入"晚上九点半也没有再疼"，九点半当时还没到）。
- **`describe_when`**：今天/明天/后天/还有 N 天/昨天/已经过去 N 天；对命中"约定线索词"的条目额外加一句"**这个约定已经过期了，不要再说成还没发生**"；时刻级再加"**就是今天，但约定时刻（N 点）已经过了，不要再说成还没发生，更不要发出邀约**"。
- **两张线索表的宽窄是刻意的**：`PLAN_HINT`（宽，含"见面/碰头"）用于时距提醒；`PLAN_COMMIT`（窄，不含中性"见面/碰头"）用于"过期约定过滤"——真实数据里"见面时带了小饼干"是**已发生**的事，用宽表会被当成过期约定抹掉一段共同经历。

### 8.2 天气（`utils/weather.py`）

| 设计 | 要点 |
|---|---|
| 数据源 | 高德 Web 服务；两次调用组装（`extensions=base` 实况 + `extensions=all` 今天/明天预报）；`status != "1"` 视为失败 |
| 缓存 | `WeatherCache`，TTL 默认 3600s（下限 60s）；`enabled` 需 key 与 city 同时非空（没配就整体静默关闭） |
| **职责分离** | `refresh()` 可能联网，**只在后台调**；`line()` **只读缓存、永不阻塞、永不抛异常** |
| 失败策略 | 失败也记账（更新 `_ts`，避免每轮重试打爆接口）→ 退回 **last-known-good** → 连上次都没有就返回 `None`（不注入） |
| 注入格式 | `城市，天气 温度°C，风向风 风力`（城市去掉"市"），有昼夜差异/明日预报时追加 |
| **话术边界** | 只给一行事实，**不写"下雨就说带伞"这类 if-then**（工具给事实，人格给话术） |
| 调用时机 | 启动拉一次（**异常只 WARNING，不阻断启动**——踩过 `#070`：一次超时让整个服务起不来）；每轮回答后再刷一次，异常静默 |
| 位置（城市从哪来） | **先定城市、再拉天气**（`#109`）：① 世界书（`_city_from_world`：只认含「住在／所在／常驻」的句子，`/city` 写进去、重启不丢）→ ② `WB_AMAP_CITY` → ③ **都没有就不猜**：天气与附近推荐关掉 + 启动 WARNING。老代码的顺序是反的（先按写死的 `330100`=杭州拉一次，再被世界书覆盖成真实城市 → 白拉一次 + 日志像她认错城市，用户 2026-09-29 重启时看到的正是这个） |
| 没有城市时的影响面 | 天气块不注入；**「附近」整条关掉**（`_nearby_for` 在 `weather.enabled` 为假时直接返回空）——猜一个城市去推荐店铺比不推荐更糟 |

### 8.3 情绪轨迹（`models/emotion.py`）

- **模型**：jev（TypeSafe System One 决策模型，经中转），协议**不是 OpenAI**（`POST {base}/systemone`，发 `state` + 类型化问题，回**概率 + 置信度**）。
- **两类问题**：`mood`（7 类：开心/平静/低落/烦躁/焦虑/生气/委屈）+ `intensity`（4 级 score）。
- **门槛与保留**：`confidence < 0.6` **不记录**（"低置信度不行动"）；choice 不在 7 类内也不记；轨迹只留 **14 天**。
- **记录字段**：`ts / mood / confidence(2 位) / intensity(1–5) / quote(用户原话前 40 字)`。
- **落盘**：原子写；失败只 WARNING（情绪掉线不能挂对话），日志写明"这次只在内存里，重启就没了"。
- **注入规则（`summary()` 返回一行，没有值得说的返回 `None`）**：
  · 近 2 天 ≥2 次负面（intensity ≥3）→ "说话轻一点，先接住情绪再谈别的，别急着给建议"；
  · 仅近期有负面、无旧负面 → "这轮语气轻一点"；
  · 旧负面已消且近 2 天 mood 为开心/平静 → "可以顺着轻松一点的氛围聊"；
  · 其余 → `None`（**沉默优于噪音**）。
- **调度**：每 `EMOTION_EVERY`（默认 1）轮判一次；上下文带上上两轮摘要各截 90 字；异常 WARNING 跳过。
- **已知限制（官方口径）**：对中文与间接推理偏弱、算数日期不行 → **只让它做情绪分类**，时刻/日期一律不问它。

### 8.4 表达层：语音与"她的调调"（`utils/tts.py`）

**三层管线**：`clean_for_speech`（剥 emoji / Markdown / 代码块 / URL）→ `script_for`（韵律脚本）→ `synth_stream`（SSML 合成，被拒则降级纯文本）。

| 设计 | 要点 |
|---|---|
| **声线档案** `VOICE_PROFILE` | 想微调她的说话习惯只动这里：基线 `rate 1.0 / pitch 1.0 / volume 50`；停顿 短 240ms / 中 480ms / 思考 820ms；填充词 `["诶，","嗯…","欸，"]` 概率 0.22；思考停概率 0.18；句尾 `["哦","呀","啦"]` 概率 0.28；**全回复最多 3 处情绪标签**、太短的句子不打标签 |
| **稳定种子** | `_rng_for(answer, mood)`（md5 前 8 位）→ **同一轮回复永远同一版台词**（可复现、不抖） |
| **情绪的多维表达** | 9 类 mood（开心/高兴/兴奋/低落/难过/伤心/疲惫/烦躁/焦虑）各自一组维度：`pause_factor / volume / prosody_peak / lead_tag / tail_rise / rate_global / think_less / mid_tags`。**"欢快"不是快**：音高起伏↑、重音↑、停顿↓、句尾上扬、能量↑、局部语速 +5~10%——**每个维度独立起作用，缺一个维度就不像那个情绪** |
| 标签白名单 | `[sad] [angry] [excited] [whispers] [laughing] [gasp] [sighing]` |
| 截断 | `trim_for_speech` 按**句子**截到 `TTS_MAX_CHARS(300)`，且放在脚本化**之前**（不切一半 SSML）；首句即超限才硬截断 |
| 合成参数 | `PlainText` + `voice` + `mp3` + `22050Hz` + `enable_ssml` + `instruction`（**单数名生效**，`instructions`/`prompt` 会被静默忽略）+ `volume/rate/pitch` |
| 流式与超时 | `websockets.sync.client` 边收边 yield；`TTS_TIMEOUT(30s)` 超时 → 标记 + WARNING，**已产出的音频照常使用** |
| 计费留痕 | `task-finished` 事件里的 `usage.characters` 记进 `billed`（"她说了多少字要花多少钱"可查） |
| 降级链 | **只在"一块音频都没拿到"且用过 SSML 时**，剥掉 SSML/标签重试一次纯文本；任何失败只 WARNING，文字对话不受影响 |
| 事件 | `finally` 里**无条件**记 `tts` 事件（chunks/chars/mood/first/total/billed/fallback/timeout）——客户端中途断开也记 |
| 开关 | `TTS_ENABLED` / `TTS_PROSODY`（韵律引擎回退开关）/ `TTS_VOICE` 等（见附录 D） |

### 8.5 开场白（`ChatService.greeting`）

| 设计 | 要点 |
|---|---|
| 缓存 | `force=False` 只取缓存；`GREETING=False` 返回空串；`/api/state` **只给缓存、不在 state 里生成**；真正生成入口是 `/api/greeting`（force=True） |
| **生成前先清掉上一条开场白** | 否则它堆在滑动窗口里，挤掉真实对话 |
| 素材挑选 | 约定**单独挑**（`upcoming(within_days=7)`，最多 5 条）——不靠"最近 8 条记忆"，因为几天前记的约定会被闲聊挤出去；事实取"非世界书/约束且不在约定里"的最后 8 条 |
| **间隔语从最后一条"用户"消息算** | 不能算最后一条消息——否则上一条开场白会被当成"刚聊过"：<1h "几分钟前刚聊过" / <24h "约 N 小时前" / 否则 "N 天前" |
| 收尾素材 | 最近 4 条真实对话（排除开场白），每条截 60 字 |
| 生成 | `chat_text`（专用模型、temperature 0.8、max_tokens 400、关思考）→ 去引号、取首行、截 80 字；**为空或失败则退回人设里的固定台词**（`personality.greet()`） |
| 标记 | 写回会话历史时打 `greeting: True`（用于把它与真实对话区分开） |

### 8.6 她自己的生活与主动开口（`models/life.py` + `services/speak.py`，`#107`/`#108`）

这一层解决的是**"用户不在时她在干嘛"**——此前她只有"现在几点"（`8.1`）和事件日期，**用户不来，她的时间就停**。

| 设计 | 要点 |
|---|---|
| 时段切分 | 一天 **7 段**（清晨/上午/中午/下午/傍晚/晚上/深夜）；新时段边界后的 **10–50 分钟**选定推进时间并落库，到时推进。对话确认的完成进展可立即更新当前状态 |
| 每一格**她自己选** | `LIFE_PROMPT` 给她「职责与作息 / 偏好倾向 / 牵挂」+ 最近流水，让她挑这一段做什么；**"习惯"是她自己选择累积出来的**，不是写死的日程。模型不可用 → 退兜底候选（`FALLBACK`），**绝不让她停住** |
| 编剧层 `life.json` | **手写、慢变**，只给维度不给日程（没有任何一条规定"她周二晚上做什么"）；读不出来时**不覆盖原文件**（同 `T73` 纪律） |
| 状态落点 | `life_state`（单行：`在哪/在做什么/心情/牵挂/时段/时段日期/下次推进时间`）+ `life_events`（保留原文与来源；看板隐藏只更新 `hidden_at`，不删除过去经历） |
| 生活历史与隐藏 | `recent_events()` 默认只读可见流水，供看板、当前素材、偏好与判重使用；`history_for()` 按需包含隐藏流水，并标注仅作历史记录。隐藏的新流水不能绕过主动开口的报备与沉默等待闸门；当前状态不随看板隐藏改变 |
| 错过的时段 | `catch_up()` **最多补 4 格**（`MAX_CATCH_UP`）——服务关几天再开，她的流水里真有几格，**不假装"刚才还在聊"** |
| **隔离（硬边界）** | 她的生活**不进 `memories`**、不参与召回/作废/补偿，**绝不**进画像分析的输入——否则她编的"自己的生活"会污染"用户是谁"。有测试钉住 |
| 注入 | `system_prompt()` 在时间块之后插【你此刻】，**只在有状态时注入**（不留空气块），并明说"这里面没有的事不要编" |
| 主动性（结构） | 纯请求/响应**结构上做不到**"她先开口"，靠提示词补不出来 → ① `lifespan` 起低频后台线程（`_start_proactive_beat`，`WB_PROACTIVE_EVERY` 分钟一轮，首轮 ≤120s）；② 说了的话进 `pending_say` 待发表，前端 **30s 轮询** `GET /api/pending`（HTTP 推不了，只能拉）；③ `take_pending()` 用 `consumed_at` 原子标记，**取出幂等** |
| 主动性的闸门 | 总开关 → 静默时段 → 当天上限（默认 6 次）→ 可选最短间隔 → 聊天后 5 分钟静默 → 她刚决定不说时等待 → 按空闲时长抽取**判断机会**；满一小时必检查一次，但模型可以选择沉默。新生活或新对话可以提前唤起判断 |
| 内容纪律 | 可分享自己的生活、关心对方明确说过的事、说源于偏好的念头；不编生活事件或共同经历；**允许没有问句**；1~3 条短消息；禁 meta（"我主动找你""打扰你"） |
| 与记忆层的边界 | 她说的话**进 `messages`**（下轮上下文连贯），**不进 `memories`**（避免自己的话被当事实反复强化） |
| 失败姿态 | 主动说话这条链**任何环节异常都吞掉只记 WARNING**——不许影响正常对话 |

### 8.7 关系看板与承诺提醒（`models/relationship.py`，`#149`／`#150`）

关系阶段默认仍由她在复盘时决定，资格线和冷却只作护栏。承诺保存到每用户的 `relationship.json`：稳定 `p1` ID、`open/done/missed` 状态、可选明确 `due_at`；完成与失约留原记录，关系事件最多最近 100 条。

到期仅是待确认线索，不自动生成完成或失约事实。`Speaker` 提供到期快照，让模型选择是否开口；过滤后的气泡完整提到原文、且模型返回有效 `reminder_ids` 才可消费提醒。入队前重验承诺状态，入队成功后记录 `reminded_at`。静默、聊天保护、概率、日次数、沉默等待继续生效，到期仅绕过同格已报备限制。主动 tick 使用实例非阻塞锁防重入，关系读改写使用 `RLock`，写盘失败显式报错并回滚承诺内存状态。

看板 `GET /api/relationship` 展示阶段、称呼、推进理由、承诺与关系历史；新增／完成／失约接口沿用 `svc(request)` 的鉴权和用户隔离。前端按稳定 ID 操作，防账号／页面变化和乱序响应覆盖。JSON 与待发表 SQLite 不是单事务，入队后记账前崩溃可能再次提醒。

## 9. LLM 调用层（`utils/llmjson.py`）

**两个通用兜底**（在推理模型上踩出来的：thinking token 吃掉额度 → 正文为空 / JSON 截断）：
1. 正文为空时**回退读 `reasoning_content`**；
2. **截断 JSON 修补**：剥 ```json 围栏 → 取第一个 `{...}` → 依次尝试补尾巴（`""`, `"}"`, `"]}"`, `"\""}"`, `"\"]}}"`）→ 失败返回 `None`。
3. `strings(data, *keys)`：数组字段安全取成字符串列表（去重去空）——所有"从模型拿列表"的地方共用，防形状漂移。

**关思考**：按"参数族"发（`thinking` / `enable_thinking` / 供应商别名），一次只发一族（两族同塞会被老服务端报参数错）；**写法不认识时不再静默**，打 WARNING 并按"不关"处理。
**失败的返回值约定**：拿不到就返回 `(None, err)`，调用方必须显式处理（写路径 → 本轮不写；读路径 → 空块；人格/画像 → 保留旧值并留痕）。

## 10. 服务编排与并发

- **一轮的三种调用**：`prepare()`（组 messages：1 次 embedding + 全部注入）→ `ask()`（主对话）→ `finish_turn()`（写记忆 + 落盘 + 天气刷新 + 情绪 + 留证现场 + 画像/人格调度）。流式接口把 `prepare` 留在请求里、`finish_turn` 交给后台。
- **实例注册**（`registry`）：按 uid 缓存 `ChatService`，上限 `WB_MAX_SERVICES(50)`，LRU 回收**但跳过被借出的实例**（引用计数），全在用则**告警不回收**（软上限）。`drop()` 只移出缓存 + `close()`（close 会先 save 再关连接，否则 Windows 上删不掉 `memory.db`）。
- **后台 worker**：`WB_WORKERS(2)` 个线程，按 `crc32(uid) % N` **分片** → 同用户天然串行；退出 `flush(60s)`（否则丢最后几轮记忆）；刻意不引入 Redis/Kafka。
- **配额**：`WB_DAILY_TURNS(300)` 轮/天，按 uid 内存计数（跨天自动重置；被拒时给出恢复时间）；闸门只加在真正产出对话的两个接口上。
- **启动/关闭时序**（lifespan）：预热默认用户实例（把"首次请求慢"挪到启动）→ 启动 worker → 退出时 `flush` + 每个用户跑一次待办（人格演化/摘要）+ `close_all`。
- **并发安全的三条硬约定**：① 锁**不跨模型调用**；② 向量与元数据**成对**写入；③ 一次计算里**只读一次**共享引用（`vectors` 下标＝`memories` 下标，中途被改会张冠李戴甚至 500）。

- **组织**：`index.html`（结构 + Tailwind 类）＋ `js/{api,sse,audio,app}.js`（ES module）＋ `assets/`（编译后的 CSS、33 个本地 Lucide 图标、本地 vendored `eventsource-parser`）。

- **守卫测试**（构建漂移）：类名漂移 / **JS 选择器钩子在页面里必须存在** / 图标管线（svg + CSS 规则）/ `@source` 登记 / 零 CDN——五项，零依赖纯文件检查。
- **主要交互**（逐条）：
  · **启动**：`?token=` 迁移进 localStorage 并清掉 URL → 匿名拉 `/api/healthz` → 若后端不支持密码登录则提示"请重启服务" → 恢复身份（token 走 `/api/auth/me` 校验，失败则清掉昵称身份）
  · **登录/首次建号**：`account_setup_required` 决定是"建号"还是"登录"；建号模式多一个确认密码与**"关联我原来的世界书、时间轴和画像"**勾选框；前端先校验 8–128 与两次一致；建号撞 409 时重拉 health 重判（另一个标签页先建好了）
  · **进入应用**：渲染 state → 显示账号名与首字头像 → 进入对话视图 → 拉 `/api/greeting` 填第一条气泡；失败则移除占位并提示"开场白暂未加载，仍然可以继续聊天"；开场白结束后检查 `/api/auth/legacy`，有可认领旧记忆时弹出确认对话框
  · **流式对话**：以 `/` 开头走 `/api/command`，否则 POST `/api/chat/stream`；`meta` → 渲染"想起了 N 条"（带相似度两位小数）；`delta` → 累加进气泡；`done` → 无正文时明说"这次没有收到回复正文"，把 `memory_note`/`profile_note` 作为系统消息展示，启用反馈按钮，`memory_async` 时在 1.8s / 5s 各刷一次状态
  · **停止回复**：组合"外部 + 内部"两个 AbortSignal（换身份时也要能中断）
  · **语音**：首个 `audio` 事件时 `audio.start()` → 逐块 `push(base64)` → `audio_end` 时 `end()`；本轮中途关掉语音 → 丢弃音频并 toast"这次语音暂未播放，文字回复已保留"；开关状态写 localStorage
  · **世界书**：列表带来源徽章（手动记录 / 来自对话）、删除按钮、"整理"按钮走 `/world tidy`、底部表单新增
  · **记忆页**：侧栏 6 个视图；`/slots`、`/timeline` 通过命令接口取值；"记忆体检"首次进入自动跑 `/mem check`；"运行状态"折叠里显示对话模型/服务/后台模型/记忆规模
  · **反馈**：底部"她说错了"→ 原生 `<dialog>` 填备注 → `POST /api/feedback` → 把后端返回的那句话作为系统消息显示
  · **命令面板**：17 个预置命令，点击后关闭面板、回到对话、把命令**填进输入框**（不自动发送——给用户改的机会）
  · **换身份/退出**：清空 abort 流、停音频、清各种定时器、关 dialog、清空各输出区与输入框
- **可访问性与降级**：skip-link（跳到消息输入）；`role=log/status/alert` + `aria-live`；图标一律 `aria-hidden` 且按钮带 `aria-label`；导航项 `aria-current`；移动端侧栏抽屉用 `inert` + `role=dialog` + `aria-modal` + **手写焦点循环** + Escape 关闭；`title` 统一换成自绘 `data-tooltip`（`role=tooltip`）；忙碌态 `aria-busy`；`prefers-reduced-motion` 下过渡压到 0.01ms；`<noscript>` 提示；无 `response.body` 时提示"浏览器未提供流式回复"；401 统一回登录屏。
- **音频降级链**：MediaSource 不支持 → 直接 Blob 播放；MSE 中途失败 → **保留全部已收块**再走 Blob（"mid-stream MSE failure loses no audio"）；`play()` 被浏览器拒绝 → 一次 toast + "播放"按钮重试。

## 13. 多用户与鉴权

- **隔离**：每用户一个数据目录（见 2.4）；实例按 uid 缓存（见第 10 节）；`data_uid` 支持"新账号继承根目录旧数据"。
- **账号**：密码 PBKDF2-HMAC-SHA256（600k 次迭代）+ 随机盐；登录签发 7 天会话令牌；**只存 sha256**；重置密码会吊销该用户全部令牌。
- **限流/同源**：登录 5 次/60 秒；校验同源；昵称编码还原（**不带标记但解出来是非 ASCII 的也还原**，避免同一昵称分裂成两个数据目录）。
- **删号**：吊销令牌 → 移出实例缓存 → 删目录 → **残留检查**（删不干净报 500，不假装成功）→ 删账号。
- **配额**：每用户每日轮数（见第 10 节）。

## 14. 评测与测试设施

### 14.1 行为基准（`benchmark/run_bench.py` + `cases.json`）

- **指标口径**：
  · **CSR（用例正确率）**：单条用例是否通过；
  · **完整率（slot_recall）**：`命中槽位 / 期望槽位`（按**槽位**算，不是按段落）；
  · **幻觉率**：`违规断言 / (命中 + 违规)`，其中违规含**陈旧 / 混淆 / 幻觉**三类；
  · 规则层能断言的绝不交给裁判（零成本）。
- **豁免设计**："滨江呀，上个月刚从城西搬过去的"是把旧值当过去时态交代的**正确答案**——取命中位置前后 25 字邻域，出现"以前/改/搬/后来"等豁免词就判合法。**宁可漏判也不冤枉**，需要严格把关的用例另设 `judge_required`。
- **隔离**：每条用例独立数据目录；`--fresh` 重建、`--repeat N` 重复、`--rescore` 重算报告。

### 14.2 人格评测（`benchmark/run_persona.py`）——**不打分**

四件套：① **互斥分类**（类别 + `ok_class`）② **强迫选择**（有人设 vs 无人设、**随机左右**、允许平局）③ **三选一辨识**（随机基线 33%）④ **矛盾检测**（只报确定的、两条互斥的）。
**为什么不用 1–5 分**：没有基准；裁判抖动会淹没结论；分数会把"她否认了人格"和"她列点用了编号"压成同一个数字；**人格的本质是关系与一致性，不是刻度**。
`--repeat` 是**强制**的：单次结果只标"仅供诊断"（每条都重新生成回答，两批比的其实不是同一段话）。
`PERS12`/`PERS13` 分别考她从既有地点偏好、已记录的自主生活选择出发作日常小决定；生活夹具只给有人设组。矛盾检测按每遍分开跑，避免把不同遍的随机回答当成同一次对话里的互相翻案。

### 14.3 实验工具（`benchmark/run_opinions.py`）

给"注入几条倾向/怎么写"定的实验台：合成倾向集 + 7 条探针 + 独立裁判；三条曲线（遵守率 / 误用与系统腔 / 该表态时有没有被压住）；`--n` 选条数、`--wording` 选措辞、`--select top|relevant` 选策略。**结论见第 6 节**。

## 16. 工程制度

**工程纪律**：
1. **动手前先读设计文档与相关测试**；大块改动前先确认基线是绿的。
2. **每条改动必须带可复现的验证证据**（命令 + 真实输出）；"我改好了"不是证据。
3. **结论从报告 JSON 取**，终端输出只用来判断"跑没跑通"（被截断的输出尤其不能读结论）。
4. **同一文件同一轮不连改多次**：改一次、重读一次、再改下一次。
5. **文档滞后于代码时，以代码为准**。
6. **隐私文件不进版本库**：`.env`、数据库、日志、用户目录、评测结果都由 `.gitignore` 挡住。

**文档分工**：代码＝唯一真相；`DECISIONS.md`＝为什么这么设计与被否决的替代；`架构/项目总览/技术栈`＝结构流程依赖；`README`＝对外行为与限制；**本文＝设计全貌**。

**代码里的设计纪律**（示例，逐条都在注释里带实测依据）：
· 失败要可见（6 条不变式之一，出现在向量化/摘要/人格检查/关思考/淘汰五个位置）
· 留档必须有出口（归档/事件都有上限）
· 宁可漏也别误（世界书判定失败按新增、日期拿不准不写、词表刻意收窄）
· 工具给事实、人格给话术
· 拦下 ≠ 丢弃（人格冲突留档等拍板）
· 先观测再谈新增（机制跑没跑靠事件表回答）
· 涉及删改的自动化宁可交给人（对账**只报告不改数据**）

## 17. 已知边界与未决

1. **单人自用**：没有真实用户量，也没有多实例并发压测（SQLite 单写）。
2. **评测样本偏少**：47 条行为基准、13 条人格探针 ×3 次——够"发现自己退化"，不是通用结论。
3. **两条兜底机制未被真实数据触发**：`compensate`/`superseded` 在真实库里从未出现（只在受控场景验证过）——**对外讲述时不能说成"线上一直靠它兜底"**。
4. **对账结果目前只做提示**：有界面消费（记忆体检），但不影响行为；要不要接自动化是产品决定。
5. **时间轴只做可见性**，尚未注入上下文（注入前需先做"同一事件多措辞"的合并）。
6. **语音没人工实听**（代码与分段都测了，听感没验）。
7. **多人格的"每人一个她"**已落地（目录+实例+鉴权+配额）；`#156` 已补产品侧"认领旧数据"入口（登录后提示、用户确认、重复提交幂等、并发切换护栏）。
8. **倾向机制的两级门槛**（独立命中 ≥2 + 有备注）目前还偏严：真实反馈量小时很难晋升——这是刻意的保守，数据多了再复核阈值与注入条数。
9. **记忆单调增长**（除归档/事件有上限外）：长期运行的体积与淘汰策略需要真实数据再评估。
10. **两处"文档说了但文件不在"**（`#96` 复核）：`docs/需求文档.md`（台账 `#93` 与 README 都引用）与 `docs/前端交付说明.md`（`scripts/export-frontend.mjs` 会生成它）**当前都不在 `docs/` 下**。要么补上、要么改掉引用。
11. **一处文档互相矛盾**：`README.md` 的"已知限制"仍写着镜像"尚未真实构建（T60）"，而 `Dockerfile` 里记的是 `#87` **已验证构建成功（61s / 327MB）**。**以 `Dockerfile` 为准**（它带具体数字），README 那句需要同步。
12. **限流与配额是单实例内存态**：登录限流（DATA_DIR+客户端 IP+用户名三元组）与每日配额都在进程内存里，重启清零、多实例不共享；对外多实例前要重新设计。
13. **无监控/告警、无 CI**：验证靠人跑（台账要求每条改动附命令与输出），没有自动化流水线。

## 18. 入口、脚本与数据迁移

### 18.1 两个 View 共用一套 Service（分层落点）

| 入口 | 干什么 |
|---|---|
| `python web.py` | 浏览器版：`uvicorn` 起 `app.main:app`，**只监听 127.0.0.1**（不对外暴露），端口取 `config.PORT`（默认 8765） |
| `python openai_hello.py` | 命令行版：一样的能力 |
| `app/views/index.html` + `js/` | 网页 View |
| `app/controllers/` | HTTP 进出口（Controller） |
| `app/services/chat_service.py` | 一轮对话怎么编排（Service） |
| `app/models/` | 记忆、人格、世界书、画像、情绪（Model） |

**两个 View 行为一致的保证**：业务逻辑只在 Service 层一份——改一处，命令行与网页同时生效。（分层：View → Controller → Service → Model + `utils/`。）

### 18.2 脚本（`scripts/`）

| 脚本 | 作用 |
|---|---|
| `build-frontend.mjs` | 前端构建：拷 33 个 Lucide 图标 + vendored `eventsource-parser` + 许可证 → 生成 `icons.css` → 跑 Tailwind CLI 编译 `assets/styles.css` |

### 18.3 旧数据迁移（一次性、可复跑）

1. **JSON → SQLite**：旧格式 `memory_data.json` + `memory_data_vecs.npy` 启动时迁进 `memory.db`，迁完改名 `*.migrated`（不删，留证据）。
2. **列迁移**：`event_date`（时间轴）、`actor`（是谁的经历）、`relaxed_at`（约束解除）三列是后来加的，旧库在连接时 `ALTER TABLE` 补齐。
3. **`event_date` 存量补跑**：老条目全是 NULL，加载期用纯函数 `find_date` 补一遍（**只补能解析出来的**，不硬造）。
4. **相对词重锚**：换算法前的条目按**它自己的 `ts`** 把"明天/下周"重写成绝对日期，旧向量作废、走补算流程重算。
5. **`pending` 表孤儿捡回**：表里若有"没有对应 memories 行"的文本（迁移遗留），加载时重新登记成正式记忆补向量，并 WARNING 说明捡回几条。
