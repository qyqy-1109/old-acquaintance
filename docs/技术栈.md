# 技术栈说明

> 生成时间；**2026-09-27 晚追加**：鉴权（令牌+哈希库）/ 多用户（每用户数据目录 + registry LRU）/ 每日配额 / 异步写记忆（worker）/ 健康检查 / Docker 最小部署件 / **记忆库按职责拆成主类 + 7 个 Mixin** / 离线测试
> 依赖版本取自根目录 `requirements.txt`，并与本机实测环境（Python 3.13.15 / conda 环境 `test_py313`）一致。⚠️ **默认解释器 `D:\conda\python.exe` 没有 openai**：起服务/跑 benchmark 必须用 `test_py313`。

## 一、总体技术路线

单进程本地运行的对话型 Agent 应用：Python 后端（FastAPI + SQLite）+ 原生 HTML / TailwindCSS / ES Modules 前端 + OpenAI 兼容接口的第三方大模型 API。**没有向量数据库、没有嵌入式本地模型、没有消息队列**，向量检索用 numpy 矩阵乘法在内存中完成。

## 五、构建工具与工程化配置

后端为源码直接运行；前端使用 `npm run build:frontend` 编译 TailwindCSS，并复制本地图标和 SSE 解析器。编译产物随项目保留，启动后端无需 Node.js。

- **依赖声明**：根目录 `requirements.txt`，只锁 6 个直接 import 的包（fastapi / uvicorn / pydantic / openai / numpy / **websockets**），传递依赖（starlette、httpx、anyio 等）交给 pip 自己解；注释里写明了「哪几个包升级要重测」的原因
- **没有** `pyproject.toml` / `setup.py`；**没有** lint / format / CI 配置
- **测试**：`tests/test_pure.py`（离线脚本式），零依赖的脚本式测试（刻意不引 pytest），跑法 `python tests/test_pure.py`。四层覆盖：
  - **纯函数**：日期解析、时距标注、当前时间文本、人格字段迁移、时刻级解析、写入哨兵、相对词重锚；
  - **记忆机制**：用临时 SQLite 库 + 假模型（**不联网、不调模型**）覆盖摘要游标、提炼失败隔离、容量淘汰、约束解除与持久化、状态派生的分寸、机制埋点、并发对齐；
  - **护栏**：人格白名单/底座逐字不变（含**变异验证**——故意破坏后测试必须变红）、约束块措辞、关思考族名、TTS 参数与按句截断。
  - **鉴权/多用户/配额/worker**：令牌签发与解析（无效必须 None）、svc 强制 401、每用户数据隔离、registry 借出保护、用户删除闭环、队列串行与 flush。
  - ⚠️ 该脚本会把标准输出**原地**切成 UTF-8：Windows 控制台默认 GBK，否则打印 `✓` 会抛 `UnicodeEncodeError`，断言全过却返回码 1（"假失败"）。
- **部署**：`Dockerfile`（`python:3.13-slim`，`DATA_DIR=/data` 数据卷，时区 `Asia/Shanghai`，密钥走 `--env-file .env`）+ `.dockerignore`（排掉 `.env` 与运行时数据）。**对外必须 `-e WB_AUTH_REQUIRED=1`**。⚠ 镜像尚未真实构建（T60）。
- 运行方式（两种入口）：
  - `python web.py` —— 启动本地 Web 服务，监听 `127.0.0.1:8765`（`app/config.py` 中的 `HOST` / `PORT`）
  - `python openai_hello.py` —— 命令行交互版，与 Web 版共用同一个 `ChatService`
  - 等价启动：`uvicorn app.main:app --reload`（见 `app/main.py` 模块注释）

## 六、外部模型与感知服务

### OpenAI 兼容接口（走 openai SDK）

所有模型通过 OpenAI 兼容 SDK 调用，供应商与模型名集中在 `app/config.py`，全部支持环境变量覆盖（`WB_*` 前缀）。当前**默认配置**：

| 角色 | 默认模型 | 端点 | 说明 |
|---|---|---|---|
| 主对话（`MODEL`） | `mimo-v2.6-flash` | 小米 `api.xiaomimimo.com/v1` | 流式输出。`CHAT_NO_THINK` **默认 `"off"`（不关思考）**：关掉它会伤否定式偏好一类（8 样本：漏 `no` 8/8 vs 3/8，`#028`），想省 0.77s 首字延迟再设 `thinking`（族名取值见 `CHAT_NO_THINK_DEFAULT`）；`enable_thinking` 族在 mimo 上会被**静默忽略**（T23 / `#025`） |
| 后台任务（`EXTRACT_MODEL`） | `mimo-v2.6-flash` | 同上 | 记忆提炼、世界书查重、会话摘要、性格迭代，`NO_THINK=True` |
| 画像分析（`PROFILE_MODEL`） | `mimo-v2.6-flash` | 同上 | 每 5 轮（`PROFILE_EVERY`）跑一次 |
| 开场白（`GREETING_MODEL`） | `mimo-v2.6-flash` | 同上 | 页面打开/刷新时按最新记忆生成 |
| Embedding（`EMBED_MODEL`） | `qwen3.7-text-embedding` | 千问兼容端点 | `EMBED_DIMENSIONS=2048`；embedding 单独走一套 `WB_EMBED_*` 密钥/端点 |
| 天气（感知层） | 高德 REST API `restapi.amap.com/v3/weather` | 高德 | `WB_AMAP_KEY` / `WB_AMAP_CITY`（**默认空**＝不知道你在哪就不猜；城市主要来自世界书）/ `WB_WEATHER_TTL`；1h 缓存 + last-known-good + 失败静默 |
| 情绪判断（感知层） | `jev-1.13`（TypeSafe **System One 决策模型**，非聊天模型） | `api.tu-zi.com/v1` 中转 | `WB_EMOTION_BASE_URL` / `WB_EMOTION_API_KEY`；`POST /systemone` 发类型化问题，返回概率+置信度；conf<0.6 不记录 |

感知层两个服务都用标准库 `urllib` 直连，**感知层自身没有新增 pip 依赖**。
（**全项目唯一的第三方新依赖是 TTS 引入的 `websockets`**，见上表——别把"感知层不加依赖"误读成"整个项目不加依赖"。）未配密钥时自动关闭。

要点：

- **双 provider 设计**：主对话（`CHAT_API_KEY`/`CHAT_BASE_URL`）、后台任务与文本调用（`API_KEY`/`BASE_URL`）、embedding（`EMBED_API_KEY`/`EMBED_BASE_URL`）三套凭据互相独立，可分别指向不同供应商；未单独配置时复用主客户端。
- 关思考的写法因供应商而异，`config.py` 用**参数族名**区分（`""` 不关 / `"thinking"` 默认 / `"enable_thinking"`），旧供应商名 `zhipu` / `qwen` 只作别名保留；`llmjson._create()` 在模型不支持关思考时自动退回默认行为。
- **智谱已于 2026-09 退出链路**（账户无余额）：现在主对话与后台任务都指向小米 `mimo-v2.6-flash`，embedding 走千问中转，情绪判定走 tu-zi。`config.py` 里仍留有 glm 系的**历史选型注释**，那是过程记录，当前实际默认值以上表为准。
- ✅ 安全现状：API key **外置到项目根的 `.env`**（不进版本库，见 `.gitignore`）；模板是 `.env.example`，加载器 `app/utils/envfile.py`（**环境变量优先**），缺必需 key 时启动会打印明确警告。代码里没有任何密钥明文。**本文档刻意不引用具体密钥值。**

## 七、基准测评工具（辅助设施）

| 工具 | 内容 |
|---|---|
| `benchmark/run_bench.py`（约 700 行） | 记忆能力自动测评 runner：注入 → 延迟 → 探测 → 打分。参数：`--layer recall` / `--judge`（裁判兜底规则层）/ `--fresh`（隔离目录 `benchmark/_bdata`，含 Windows 文件占用处理）/ `--repeat N`（重复跑，把「≥8 样本」纪律工具化）/ `--rescore`（离线重评，零 API 成本）。用例隔离 + **清完自检**，没清干净就打 ⚠ |
| `benchmark/cases.json` | **47 条**记忆用例（含 meta 与 cases；`B13` 覆盖「一轮多条世界书设定 → 批量判定」路径） |
| `benchmark/run_persona.py` + `persona_cases.json` | **人格评测**：13 条手写探针，四件套判定（分类 / 强迫选择 / 辨识 / 矛盾检测），**全部不打分**；带无人设对照与演化对照；隔离目录 `benchmark/_pdata`。⚠ **输入（回答）每次都是当场新生成的**，②强迫选择 / ③辨识的单次结论会摆动 → 单次仅供诊断，下结论要 `--repeat 3` 起；报告用 `single_run` 字段标出 |
| `benchmark/results/` | 历次测评结果 JSON 归档（记忆 + 人格） |

两个 runner 都复用生产代码（直接 import `app.config` / `ChatService` / `MemoryStore` / `Personality`），通过环境变量 `DATA_DIR` 把数据指到各自的隔离目录。

## 八、数据文件（运行时产物，位于项目根目录或 `$DATA_DIR`）

| 文件 | 内容 |
|---|---|
| `accounts.db` | 账号表保存 `uid`、PBKDF2 密码哈希和唯一 `data_uid`；令牌表保存 SHA256 摘要、用户、创建与到期时间。登录会话 7 天，旧管理令牌兼容；首次本机账号可关联根目录原有记忆 |
| `users/<id>/` | 多用户数据目录（2026-09-27 晚起）：每个用户自己的 `memory.db` / `personality.json` / `user_profile.json` / `world.json` / `emotion.json` / `feedback.jsonl`；`user_id` 为空时沿用根目录（默认用户） |
| `memory.db`（+ WAL / SHM） | SQLite 记忆库（**多张表**：`memories` / `messages` / `summaries` / `pending` / `slots` / `events` / `meta`，另有 SQLite 自建的 `sqlite_sequence`）。`memories` 带 `event_date`（事件日期）、`actor`（user/assistant 视角）、`relaxed_at`（约束失效时刻）；`slots` 是覆盖式状态槽位；`events` 是只增的机制埋点流水（超 `events_keep` 后在 `save()` 里修剪最老的） |
| `personality.json` | 性格模板当前值 + 历史版本（最多 20 版） |
| `world.json` | 世界书条目（唯一真相，可手写） |
| `user_profile.json` | 用户画像 |
| `emotion.json` | 用户情绪轨迹（jev 判定，conf<0.6 不记录，只留 14 天） |
| `feedback.jsonl` | 「她说错了」留证：上一轮的问题、回答、召回明细、注入的 system 块（首次点击后生成） |
| `logs/app.log`（+ `app.log.<日期>`） | 统一日志：`app.*` 命名空间，控制台 + 按天滚动文件（留 14 天），uvicorn 的 error/access 也接进来 |
| `*.json.migrated` / `*.npy.migrated` | 旧版 JSON+npy 记忆格式迁移后改名保留的原文件 |
| `memory.db.bak-*` | 历次数据迁移/清洗前的备份（`dim2048`、`stale-time`、`eventdate`、`future-time`、`reanchor`） |
