# 我的项目 vs Hindsight：逐维度对比

> 初稿 2026-09-28 上午；**同日更新**：`③ opinion with confidence` 已落地（`#088` 三轮实验 + `#089` 实现 + `D31` 设计规则）、Docker 镜像真建真跑（`#087`，T60 结案）、产品改名（产品 = **旧识**，她 = **沈知夏**，`#090`）。本文相应更新。Hindsight 资料来源：官方论文（arXiv:2512.12818，Vectorize.io + Virginia Tech + 华盛顿邮报）、官方博客（20k stars 版本史）、GitHub 仓库与第三方评测。所有「本项目」数字均出自本仓库实测记录与 `benchmark/results/`（本地评测结果，不入库）。

## 一、一句话结论

**Hindsight 是「记忆中间件」赛道里目前最强、也最像你这个项目的对手**：它的四个记忆网络和你的四层设计几乎是同构的（世界网络 ≈ 世界书、经历网络 ≈ 她的经历、观察网络 ≈ 画像+槽位、指令 ≈ 约束）。差别在于：它把「认识论分离」（事实 vs 信念）做到了检索层，检索是四路并行 + 重排，工程化程度高两个量级；而你独有的东西它一条都没有——**人格演化与可辨识性评测、感知层、旧记录退场的显式语义（软删/补偿/解除）、机制埋点与留证、陪伴形态**。结论：不必换、不必接；它是很好的「对照物」——同构证明方向一致，差异说明哪些部分它没有做。

## 三、四个记忆网络 vs 我的四层：几乎是同构的

这是这份对比里最值得注意的发现——**双方在「分层直觉」上独立收敛到了同一个答案**。

| Hindsight 网络 | 存什么（论文口径） | 我的项目里的对应物 | 同构度 |
|---|---|---|---|
| **World network**（世界网络） | 客观事实：「Python 3.12 发布了」 | **世界书** `world.json`（长期设定，唯一真相，三态判定矛盾即作废） | ★★★ 几乎一致 |
| **Experience network**（经历网络） | Agent 自己干过啥：「我帮你修了登录 bug」 | **她的经历**：提炼第 5 类 `selfs`，`actor=assistant`，进时间轴标〔她〕 | ★★★ 几乎一致（我 09-23 独立做的） |
| **Observation network**（观察网络） | 实体的中性摘要：「张三，后端工程师，擅长 Go」，带合并去重 | **用户画像** `user_profile.json` + **属性槽位** `slots`（覆盖式的"现在是什么样"） | ★★☆ 分散在三处，它聚成一层 |
| **Opinion network**（信念网络） | **带置信度的判断**：「方案大概率可行(0.85)」，会演化 | **已补齐（09-28）**：`opinions` 表——「她说错了」反馈沉淀成沟通倾向（topic 去重、**独立命中 = 会话@日期不同**、置信度 = `1−0.5^独立命中` 现算），按档注入【他在意的】（≤3 条 + 防误用框法），够格晋升进人格「待确认」**等人拍板**（`#089`/D31） | ★★★ 形态不同：它从交互自动归纳，我**反馈驱动 + 人拍板** |
| **Memory banks** | 每用户/每项目隔离的库 | **多用户**：`users/<id>/` 每用户一套数据目录 | ★★★ 一致（它叫 bank，我叫目录） |
| **Directives**（行为指令） | 可配置的行为画像 | **约束** `constraint`：不召回、每轮无条件注入、「已解除」生命周期 | ★★★ 一致 |
| **Mental models** | **会自我刷新的常驻答案**：带 staleness 信号、历史 diff、标签触发 | **部分对应**：`upcoming()` + 过期约定标注 + 开场白约定标签——但我的不自动刷新，它的会 | ★★☆ 值得借鉴 |

**一句话**：它的「认识论清晰」（证据和推断不搅在一起）四分法，和我的「四层按谁能写划权」解决的是同一个问题——**事实与推断、长期与状态不能混存**。两边独立收敛，说明这个分层是对的。

## 四、三个操作 vs 我的管线

| Hindsight 操作 | 干什么 | 我的对应物 |
|---|---|---|
| **retain** | LLM 提取事实/实体/时间关系，归一化入库 | `add_turn()` 写入管线：六类提炼 → 写入哨兵 → 作废分流 → 补偿 → 兜底追问（我的**多四步退场语义**，见第五节） |
| **recall** | **四路并行检索**（语义向量 / BM25 关键词 / 图遍历 / 时间过滤）+ 交叉编码器重排 | 单路向量召回 + 阈值 + 弱相关标注；**时间**只做了过期硬过滤与 `upcoming()`，**关键词/图遍历**没有 |
| **reflect** | 在已有记忆间发现新关联，形成更深的理解（含 disposition-aware 应答） | **没有**。最接近的是「演化」（复盘对话改人设）和对账（只报告矛盾）——但都不是 reflect |

**检索是它最强、我最弱的一环**。四路并行的理由和我的实测互相印证：我在 FTS5 对照实验里已经证明「中文短句间常无字面重叠」（纯关键词 0/10）、「纯向量也有召不回的」（约束失效 B05）——它把两条路都建了再加图与时间，是同一条教训的更完整解法。

## 五、逐维度对比

| 维度 | Hindsight | 我的项目 | 谁强 |
|---|---|---|---|
| **检索** | 四路并行（语义/BM25/图遍历/时间过滤）+ 交叉编码器重排 + RRF 融合 | 单路向量 + 阈值 0.45 + 过期硬过滤 | **它**（明显） |
| **旧值退场** | observation 合并去重（consolidation）；事实-信念分离让"改判断"有处安放；**没有显式的软删归档 / 连坐补偿 / "已解除"通道**（论文未提） | 软删归档 + 作废后补偿 + 状态变化词兜底追问 + 约束「已解除」+ 世界书三态矛盾判定 | **我**（退场语义更细；它靠"信念可演化"绕开） |
| **时间** | TEMPR 时序实体记忆、时间过滤是检索的一等公民 | 时刻级解析 + 写入哨兵 + 过期约定标注/硬过滤 + `event_date` 时间轴 | 各有侧重，它更体系化 |
| **人格** | 「行为指令」可配置，但**人格不演化、无度量** | **人格会演化**（20 轮小步 + 冲突「待确认」）且有评测（11 探针四件套，`--repeat 3` 基线：稳定「像」82%、可辨识 70%） | **我**（它根本没有这个维度） |
| **反馈闭环（信念）** | opinion 网络从交互自动归纳并演化，带置信度 | 「她说错了」→ opinions（topic 去重、独立命中、置信度现算）→ 注入【他在意的】→ 够格晋升人格「待确认」；**记错事实类不进该通道**（`is_style_issue` 分流）；提炼同步做（用户在等结果，D10） | **打平**（它全自动，我反馈驱动 + 人拍板——刻意选的） |
| **感知** | 无 | 天气 + 情绪轨迹（jev）+ 城市先定后拉 + 附近 POI（偏好→高德，不许编） | **我** |
| **自主生活与主动开口** | 无（纯被动 API：retain/recall/reflect 都等调用方） | 她的一天 7 个时段自动推进、每一格她自己选；后台心跳过七道闸门后**她主动来找你**，内容只来自她自己的生活流水 | **我**（它没有"她在过日子"这一层） |
| **可观测** | Control Plane UI（Constellation 实体图可视化）+ webhooks | 侧栏 + 留证 JSONL + `events` 埋点（**未进前端**） | 它（UI 成熟）；我的埋点语义更深 |
| **评测** | LongMemEval 91.4 / LoCoMo 83~90，公开评测代码与逐题查看器 | 自建 47 条记忆 + 13 条人格探针，不与公开基准可比 | **它**（数字 + 透明度） |
| **部署** | Docker / pip / 内嵌 / K8s / 云；内嵌 Postgres | 单机 Python + SQLite；Docker 镜像**已真实构建并跑通**（`#087`，T60 结案：327MB、真跑一轮对话）；监控/告警仍无 | 它（成熟两个量级），差距在收窄 |
| **成本** | 每轮多次 LLM 调用（抽取/合并/重排），配 LLM key 才能用 | 同样依赖 LLM；但 SQLite 单文件、无外部服务 | 我（轻），代价是检索上限低 |
| **规模** | Fortune 500 生产、多租户 | 单人、活跃记忆 32 条 | 它 |

## 六、四条重叠、四条独有、三条它强

**重叠（方向被对方验证）**
1. 四层/四网络的分法（事实 / 经历 / 实体摘要 / 行为指令）——独立收敛。
2. 「Agent 的经历」单独成类——我的 `selfs`、它的 experience network。
3. 行为指令常驻注入——它的 directives、我的 constraint。
4. **带置信度的信念**——它的 opinion network、我的 `opinions` 表（09-28 落地；差别在来源：它从交互自动归纳，我从用户反馈提炼，且晋升必过人这一关）。

**你独有（它没有）**
1. **人格演化 + 可辨识性评测**：它的人格是静态配置；我的人格会小步演化、有冲突「待确认」、有四件套评测回答"这次演化让人格更像了还是更飘了"。
2. **退场语义的显式机制**：软删归档、作废后补偿、约束「已解除」、状态槽位派生分寸——它的论文在"旧信息矛盾时怎么办"上靠信念分离缓解，没有我这层的机器兜底。
3. **感知层**（天气/情绪）与**陪伴形态**（开场白、时段一致、约定邀约判断）——它是给开发者的 API，没有"像个人"这一层。
4. **机制埋点 + 完整现场留证**：`events` 表 + `feedback.jsonl`——它的 benchmark viewer 很透明，但运行时的"这次为什么错"没有我的粒度。

**它强（别嘴硬）**
1. 检索（四路 + 重排）、2. 工程化与生产验证、3. 公开基准数字与评测透明度。

## 七、可以借鉴的三件事（按性价比）

1. **Observation 合并**：它把同一实体的多条事实合并成中性摘要（去重 + 置信度）。我这边「时间轴同一事件 2~3 条措辞变体」是已知待办（事件合并）——可以直接参考它的 consolidation 思路：按实体聚合 → 生成中性摘要 → 原条目降级为证据。**这是把我已有的「画像 + 槽位 + 世界书」合起来的一次升级。**
2. **Mental model 的 staleness 信号**：它的「常驻答案」自带过期信号和自动刷新。我的【今天说好的事】/ 约束已经有时效标注，但没有"自动刷新"——可以把 `upcoming()` 升级成"约定完成后自动转成一条经历 + 从待办撤下"（现在只做到过期过滤）。
3. ✅ **信念网络（opinion with confidence）——已落地**（`#088` 实验 + `#089` 实现，设计规则进 `D31`）：
   - 「她说错了」的反馈沉淀进 `opinions` 表（topic 去重；**独立命中 = 会话@日期都不同**——第一版按会话判独立，真机推演发现晋升门槛形同虚设，测试补了换天才算独立的守卫）。
   - 置信度 = `1−0.5^独立命中` **现算不落库**；模型自报的置信度虚高到 0.95，**只配当闸门**（≥0.6 才收）。
   - 按档注入【他在意的】块（≤3 条 + "相关的时候照做／不要点破来源"防误用框法——三轮 220 次调用实验：N 不是主变量，**倾向文本的三件套写法才是**：正面做法 + 点名失败动作 + 篇幅约束，缺一条她就会用反问逃避表态）。
   - 够格（≥2 独立命中 + ≥1 条备注）生成 patch 进 `/personality pending` **等人拍板**，绝不自动生效；「她记错了事实」类反馈分流走别的通道，不进风格机制。
   - 出口：`/mem opinions`。

**不建议做的**：把自建记忆换成 Hindsight（记忆本身就是研究对象，换了等于弃题）；为对标它去做图数据库/多路检索（单机单人用不上，检索上限不是当前瓶颈）。

**一个可选动作**：它的评测代码和逐题查看器公开（MIT）。如果哪天想回答「你的记忆系统放到公开基准上什么水平」，跑一次它的 LongMemEval 脚本（用它 harness 的对照组设置）是成本最低的路径——但要预期分数不好看，你的 47 条自建集和它是不同的问题。
