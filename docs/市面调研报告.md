## 一、摘要（先给结论）

1. **赛道已经分成四块**，你的项目横跨其中两块：既是「记忆中间件」的研究对象，又是「AI 陪伴 / 角色扮演」的形态。这两块的竞争逻辑完全不同，混着看会得出错误的定位。
2. **「通用召回质量」这条赛道已经很挤，别进去**：Mem0、Zep、Letta、Cognee、MemOS（国内）都有工程团队、公开基准和框架集成；Mem0 一家就宣称覆盖 21 个框架/平台。你在这个维度上必输。
3. **你真正踩中的是「全行业公认最难且无人及格」的那一类题**：2026 年 6 月发布的 `SubtleMemory` 基准（哈工大、上海 AI 实验室等六家机构）专门考「多条相关记忆之间是互补、细微区别还是**矛盾**」，结果是**所有主流记忆系统都没过关**——矛盾关系题在理想条件下 GPT-5.4 也只答对 68.7%，最好的独立记忆系统 A-Mem 整体 70.0%（理想上限 85.4%）。而「旧记录被推翻 / 约束被放宽 / 状态失效」恰恰是你投入最多的部分。
4. **陪伴类产品的记忆是「留存工具」，不是「研究对象」**：Nomi、Kindroid、Replika、猫箱都在做长期记忆，但目的是让用户回来；几乎没人在做作废语义、约束常驻、过期约定、机制埋点、人格可辨识性。**这是你的空位。**
5. **你最该补的不是技术，是「记忆对用户可见、可改、可删」**：Nomi 有可编辑的 Mind Map、猫箱有「回溯 / 清除上下文重置记忆」、MemOS 有 Memory Viewer。你的项目只有 `/mem` 系列命令和手改 `world.json`，`events` 埋点也没进前端。

## 三、第一类：记忆中间件（卖给开发者的记忆层）

| 产品 | 定位与机制（【公开文档】） | 关键数字 | 对你的意义 |
|---|---|---|---|
| **Mem0** | 混合架构（图 + 向量 + KV），可插拔后端；**单遍 ADD-only 抽取**（只增不覆盖）；**多信号检索**（语义 + BM25 + 实体匹配并行后融合）；实体链接 | 自报 LoCoMo 92.5 / LongMemEval 94.4，约 6,956 tokens/query；GitHub ~48k stars（2026 初）；托管版 $19/月起 | 行业默认选项。它的「ADD-only」意味着**它不解决旧值退场**——这正是你和它的分界线 |
| **Zep（Graphiti）** | **时态知识图谱**，双时态模型（事件时间 vs 摄入时间）+ 有效性窗口，最适合「事实随时间变化」 | 论文口径 LongMemEval 63.8%（gpt-4o-mini）/ 71.2%（gpt-4o）；站点自报 90.2 / 94.7（**不同评测设置，与 Mem0 不可比**） | 它是「时间有效性」做得最认真的一个；你的 `relaxed_at` / `event_date` 是同一思路的轻量版 |
| **Letta（原 MemGPT）** | 分层记忆（in-context / core / archival），**Agent 自编辑记忆**，强调自我内省 | 文件系统方案在 LoCoMo 74.0 | 它证明了「简单文件存储也能打」——你的 SQLite 单文件路线不丢人 |

| **MemOS（国内，MemTensor）** | **开源 Apache-2.0**；统一记忆 API；图结构**可检查可编辑（非黑盒 embedding）**；MemCube 多知识库；MemScheduler 异步；有本地插件（SQLite + FTS5 混合检索 + Memory Viewer 面板） | 自报 LoCoMo 88.83 / LongMemEval 89.20（OmniMemEval） | 国内最像「完整产品」的一个；它的**可检查可编辑**是你要对标的标准 |

## 六、第四类：评测基准（这节对你的定位最关键）

| 基准 | 考什么 | 与你的关系 |
|---|---|---|
| **LoCoMo** / **LongMemEval** | 长期对话的事实召回、多会话推理、时序推理 | Mem0/Zep/Letta 的公开分数都在这两个上；但**harness 不同能差 20+ 分**，且审计发现 ground truth 约 6.4% 有评分错误 |
| **MADial-Bench**（双语） | 不只测被动召回，还测**主动召回**与「记忆注入率」、亲密度 | 它证明「记住了」和「会在回答里用出来」是两件事——你在 B11 / S05 上踩的就是这个 |
| **PersonaMem / PrefEval / 清华 MemoryBench** | 用户画像、偏好、用户反馈下的持续学习 | 与你的人格评测同一方向 |
| **EverMemBench / MABench** | 超长上下文、多方协作、**冲突解决** | 冲突解决被单列成一项能力 |
| **SubtleMemory（2026-06，arXiv:2606.05761）** | **多条记忆之间的关系**：互补 / 细微区别 / **矛盾** | **直接对应你的主战场，见下** |

### SubtleMemory：全行业在「矛盾」上都不及格

- **出处**：哈工大 + 上海人工智能实验室 + 同济 + 厦大 + 复旦 + 上交，2026-06 预印本（arXiv:2606.05761），代码公开。
- **考卷**：1522 道题，背后 1090 组关系受控的信息变体——互补 361 组、细微区别 352 组、**矛盾 377 组**；每份历史平均 236.4 段对话、约 21.16 万词语，干扰项穿插其中。评委用 Gemini 3.1 Pro Thinking，与人工标注一致性 κ=0.963。
- **被测对象**：独立记忆系统 6 款（Mem0 / MemOS / EverMemOS / MIRIX / A-Mem / MemoBase）+ 自带记忆的助手 2 款（OpenClaw / MetaClaw）+ OpenClaw 挂三种插件。
- **结果**：理想上限（把原始对话直接喂模型，绕过记忆系统）85.4%；最好的独立系统 **A-Mem 70.0%**、Mem0 69.0%、EverMemOS 68.1%、MemOS 56.8%；MemoBase 32.1%；MetaClaw 20.3%。
- **矛盾类是最难的，没有悬念**：理想条件下 GPT-5.4 也只 **68.7%**（弱一档的 GPT-OSS-120B 只有 41.6%）；各系统在矛盾类上比另两类**低 20~30 个百分点**。OpenClaw 在矛盾类上的检索成功率只有 34.2%，最终只答对 25.5%。
- **病根**：① 冲突信息在**保存阶段**就被系统错误合并或丢弃（相互干扰）；② 模型面对无解矛盾时倾向「强行解决」——偷偷选一边，或编个理由把矛盾圆过去，**而不是诚实承认冲突**。
- **论文给的改进方向**：存储时保留更多细节（尤其时间与情境）、检索时能同时取回多条相关信息、回答时能识别矛盾并保持诚实。

**这三条和你做过的事几乎逐条对应**：
- 存储保细节 → 你的 `event_date` + 时刻级解析 + `actor` 双视角；
- 同时取回多条 → 你的约束常驻注入（不靠相似度碰运气）+ 状态槽位全量注入；
- 识别矛盾并保持诚实 → 你的世界书**三态判定（重复/矛盾/新增）**、作废 + 补偿、约束「已解除」保留记忆但撤掉禁令、【此刻的分寸】。**而且它们都是显式的、可断言的，不是靠模型自觉。**

⚠️ 但要注意：**这些是论文在通用记忆系统上测的数，不等于你的项目在这个基准上就会好**。你的 47 条是自建集，和它没有可比性。这个基准的价值是**证明方向对、需求真**，不是给你背书。

> 📌 关于本项目自己的数字怎么引用：人格评测的**首份**结果（扩展前 11 条探针，辨识 10/11）是**单次测量**，按本项目的纪律不可当结论；后来用 `--repeat 3` 跑出的**可信基线**是：稳定「像」**82%**、可辨识 **70%**（随机基线 33%）。对外一律用后者，并说明是「自建 13 条探针、不与公开基准可比」。记忆评测同理：47 条单跑波动 ±1~2 条。

## 八、三条该做的 / 三条别做的

**该做（按性价比）**
1. **把记忆做成用户可看、可改、可删的面板**——对标 Nomi 的 Mind Map 与 MemOS 的 Viewer。你的数据已经在 `memory.db` 里（含 `slots` / `event_date` / `relaxed_at`），缺的只是界面。这同时解决「人格演化一致性」的人工兜底。
2. **补上「用户侧的遗忘权」**——对标猫箱的「回溯 / 清除上下文重置记忆」。你只有 `/forget`（全清）和 `/mem del`（按数据删），没有「把某一件事抹掉」的能力。
3. **把 `events` 埋点接进前端**（已在待办：抽屉的常用命令清单没列它）。你的埋点是全行业都没有的东西，藏起来可惜。

**别做**
1. 别追通用召回质量（多信号融合、图存储、实体链接）——那是 Mem0/Zep 的主场。
2. 别接 LoCoMo / LongMemEval 刷分——harness 争议大，且不覆盖你的强项。**真想用外部基准，`SubtleMemory` 更贴**：它考的就是矛盾/细微区别，代码公开，可以只跑矛盾那 377 组看你的机制表现（成本可控，但仍是可选动作，不是必须）。
3. 别把「记忆好」当成陪伴产品的胜负手——Character.AI 记忆最弱却是用户量最大的那个。

## 九、这份调研对简历与面试的直接作用

- 可以在简历/面试里加的一句：「**选的这个细分（旧记录退场、矛盾处理）是 2026 年公开基准 SubtleMemory 认定为全行业最难、且所有主流系统都没及格的一类题**；我把它们做成了显式机制（三态判定、软删归档 + 补偿、约束解除、状态派生分寸），而不是靠模型自觉。」
- 被问「这和 Mem0 有什么区别」时，可以精确回答：「Mem0 是 **ADD-only**（只增不覆盖），它不处理旧值退场；我的工作重心恰恰在那一步，而且每一步都有可断言的注入块与埋点。」
- 被问「陪伴产品不是都有记忆吗」时：「它们做的是**留存工具**（存更多、取更准、能重置）；我做的是**退场语义与可证伪的评测**——这两件事在公开资料里找不到第二家在做。」
